Where it fits

One assistant, shaped to your site

Give it a persona and a few page tools, and it takes on the job. A few ideas:

  • Property and venue tours

    “Show me the master bedroom.”

    A tool moves the tour, and the agent describes what is on screen.

  • Help centres

    “How do I change my delivery address?”

    Answers from your persona's knowledge, then scrolls to the right section.

  • Bookings and forms

    “A table for four on Friday, please.”

    The agent fills the form fields through your tools; the visitor checks and sends.

  • Product pages

    “Which plan suits a team of five?”

    A guide that knows your catalogue, with the words on screen as it speaks.

How it works

Three steps to a talking site

  1. Add one script tag and one element

    Host the embed bundle and place <talkie-assistant> in your HTML. No bundler or framework needed.

  2. Your server mints a short-lived token

    A small server route requests the token, so your API key never reaches the browser. Only short-lived credentials do.

  3. Speech recognition, the reply and the voice run over one connection

    AssemblyAI's Voice Agent API handles transcription, the model's reply and speech synthesis over a single WebSocket, with no hops between separate services.

index.html
<script src="/path/to/talkie-embed.js" defer></script>
<talkie-assistant api="https://your-voice-server"></talkie-assistant>

<!-- Optional: let the agent act on the page -->
<script>
  document.querySelector('talkie-assistant').onToolCall =
    async ({ name, arguments: args }) => {
      if (name === 'show_room') await tour.goTo(args.room);
      return { ok: true };
    };
</script>

Features

Everything a voice assistant needs

It can act on your page

Declare function tools and the agent calls them mid-conversation: show a room, scroll to a section, fill in a form. Your handler's result goes back to the agent, so the reply matches what is on screen.

  • show_room
  • go_to_section
  • fill_booking_form

Talk naturally

Conversation mode keeps listening between turns, and visitors can talk over an answer to interrupt it. Push-to-talk is there if you prefer it.

See every word

A live transcript shows what the visitor said as it arrives, and the reply appears word by word as the voice speaks it.

Looks like your brand

Colours, fonts and the launcher come from CSS custom properties such as --talkie-paper. No shadow-DOM hacks.

At home on any screen

A bottom sheet on phones and a floating panel on desktop. Minimize the panel and the conversation keeps going.

Accessible by default

Screen readers hear every state change. It works from the keyboard (Space, Esc) and respects reduced motion.

Light, with no build step

One self-contained script to host anywhere. It adds no dependencies to your project and needs no framework.

Before you start

What you provide

  • An AssemblyAI account with an API key.
  • A token route: a few lines of server code that call AssemblyAI's token endpoint and return { token, expires_in_seconds }. See the token route in the guide.
  • A persona: a system prompt and optional voice profile. Configure it on the Persona console.
